# Everyday Mac interaction audit

Reviewed 15 October 2026. Scope: the menu-bar agenda, Marks & Feedback window, Settings, native file actions, reading controls, keyboard, pointer and accessibility journeys. This is a source-and-documentation audit, not a new UI test run. No credentials, Canvas requests or user records were accessed. Production code is unchanged.

## Evidence and interpretation

**Source** means the control/state transition is present in the current Swift files. **Recorded runtime** means `marks-feedback-verification.md` reports an earlier observed result; this audit did not reproduce it. **Pending** means a physical/runtime test is needed. The existing verification report covers selection replacement, search clearing, expansion, close/reopen, native PDF actions and light/dark appearance. It does not establish every pointer target, keyboard setting, display configuration or assistive-technology journey.

Primary implementation references: `AssignmentDates.swift`, `MenuBarController.swift`, `MenuBarSettings.swift`, `FeedbackView.swift`, `FeedbackReader.swift`, `FeedbackRubricView.swift`, `FeedbackReading.swift`, `FeedbackCopyActions.swift`, `FeedbackExport.swift`, `FeedbackPDF.swift`, and the two stores. Requirements: `AGENTS.md`, `marks-feedback-interactions.md` and `native-interaction-comparison.md`.

Priorities below describe student impact, not framework defects. P1 blocks or misdirects a core task; P2 makes a task harder or leaves an important acceptance check unresolved. Native controls provide useful defaults; their presence alone does not prove usable hit regions, focus order or spoken output.

## Display, input and accessibility acceptance matrix

The same academic task should remain possible with a built-in trackpad, external mouse, keyboard-only setup or Mac mini. Closed-display configuration is a hardware/OS prerequisite, not an app feature; follow the relevant Mac model's supported connection guidance [A8]. This audit makes no claim about a particular machine's display count or power requirements.

| Configuration | Task to execute | Pass evidence to record |
| --- | --- | --- |
| Built-in display at default scaling | Open agenda → Marks → search → expand → copy → Quick Look → close/reopen | Target locations, resulting assignment identity, selected state, returned focus; no clipped primary action. |
| External monitor at comfortable larger UI scaling | Same task at 100% and 160% reader size | Logical window size and display scale; complete file actions and rubric scores remain reachable; independent scrolling works. |
| MacBook lid closed, external keyboard/mouse | Access status item, app menus, all reading/file controls, dismiss panels | No trackpad-only or built-in-screen dependency; keyboard shortcuts work on actual keyboard layout; note Fn behavior separately. |
| Mac mini with external mouse and keyboard | Secondary-click and Control-click menus; wheel scroll; text range selection | Correct row/file targets, no reliance on Force Touch, no hover-only essential command. |
| Two monitors, move active window, then disconnect one | Keep assignment selected, reopen, invoke Save/Quick Look/Settings | Windows/panels reachable on remaining screen; source identity remains correct. Offscreen restoration is a runtime check, not a confirmed current defect. |
| Full Keyboard Access enabled | Tab/Shift-Tab through search/list/disclosures/toolbar; arrows within groups; Space activate | Visible focus and no trap, every core action reachable, clipboard command acts on focused context. Apple documents these default navigation concepts [A2]. |
| VoiceOver | Find subject/assignment/result, expand criterion, read score/comment, copy, inspect warning, dismiss preview | Names, role, expanded state, awarded/max distinction and selection announced; focus returns logically. Criterion labels now explicitly include the visible score string while respecting hidden points. Verify spoken awarded/max meaning and expanded state; the label update alone does not prove the final VoiceOver sequence. |
| Increased contrast / reduced transparency / nondefault accent | Select active/inactive rows, warnings, disabled actions, copy notice | Content source and selection remain understandable without relying on color; material notice contrast remains usable. |
| Large pointer / Hover Text / system Zoom | Hit x, toolbar menu, warning icon, criterion disclosure, file drag icon | Comfortable real hit regions; expected system cursor; help is supplemental, never the sole way to discover a core action. |

## Most useful next work

1. **P1 acceptance gate:** run one complete keyboard-only student journey, including recovery from empty search, collapsed selected subject, native Save cancel and Quick Look dismissal. Earlier isolated arrows tests do not establish the complete journey.
2. **P1 acceptance gate:** test 160% reading size on a scaled external screen at supported minimum window size. Prioritize readable criteria and reachable file actions over preserving one screenshot's geometry.
3. **P2 keyboard correctness:** file cards now support focus and Space. Test card versus descendant-button activation, repeat/Space while busy, full heading/indicator/whitespace hit regions, and Quick Look dismissal focus before claiming the complete keyboard journey passes.
4. **P2 recovery:** explicit named-copy failure and local handler failure feedback are now present in source. Exercise those outcomes and key replacement from Settings followed by feedback refresh; do not claim these runtime paths are verified yet.
5. **P2 accessibility:** native copy announcements and explicit criterion score labels are now present. Verify their actual spoken output and focus sequence; source support is a starting point, not proof of the final spoken experience.

No production fix is authorized by this document alone. Assignment instructions, course-content browsing, annotation editing, generic file-row selection and global hotkeys remain future scope; they must not be presented as current capabilities. Keep deadline layout, offline records and silent credential behavior intact.

## Primary Apple sources

- **A1 — Keyboard conventions and shortcuts:** [Apple HIG: Keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards). Standard commands and Full Keyboard Access inform the test journeys; avoid installing app-wide key interception for local controls.
- **A2 — Actual keyboard navigation settings:** [Navigate your Mac using Full Keyboard Access](https://support.apple.com/en-euro/guide/mac-help/mchlc06d1059/27/mac/27). Ordinary Tab behavior and this accessibility mode must be tested as separate conditions.
- **A3 — Pointer and accessibility design:** [Apple HIG: Pointing devices](https://developer.apple.com/design/human-interface-guidelines/pointing-devices), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility). Retain familiar mouse/trackpad behavior, system pointer appearances and multiple input routes.
- **A4 — macOS text scaling boundary:** [SwiftUI dynamicTypeSize](https://developer.apple.com/documentation/swiftui/environmentvalues/dynamictypesize). Apple explicitly states that this value does not affect text size on macOS; the app's explicit reading preference is therefore material.
- **A5 — Copy and targeting primitives:** [textSelection](https://developer.apple.com/documentation/swiftui/view/textselection(_:)), [copyable](https://developer.apple.com/documentation/swiftui/view/copyable(_:)), [selection-aware contextMenu](https://developer.apple.com/documentation/swiftui/view/contextmenu(forselectiontype:menu:primaryaction:)). These are implementation references; exact runtime hit/focus behavior still needs testing.
- **A6 — Preview lifecycle:** [quickLookPreview](https://developer.apple.com/documentation/swiftui/view/quicklookpreview(_:)). A nonnil URL presents the preview; clearing the binding dismisses it, and user dismissal clears the binding. Keyboard entry behavior is separately implemented by the app.
- **A7 — Actual file transfer:** [SentTransferredFile](https://developer.apple.com/documentation/coretransferable/senttransferredfile), [FileRepresentation](https://developer.apple.com/documentation/coretransferable/filerepresentation), [ShareLink](https://developer.apple.com/documentation/swiftui/sharelink). A transferred copy is distinct from sending a URL as text or exposing the managed original for editing.
- **A8 — Displays and supported configurations:** [Connect one or more external displays with your Mac](https://support.apple.com/en-au/guide/mac-help/mchl7c7ebe08/mac). Hardware capabilities and arrangement belong to macOS/model guidance; the app must keep its windows, content and commands usable within the available workspace.

Documentation was checked on 15 October 2026. Some Apple developer pages return a JavaScript shell to web readers; their official Markdown endpoints and searchable Apple documentation excerpts supplied the relevant text. No third-party behavior claim is used as evidence for this app.
