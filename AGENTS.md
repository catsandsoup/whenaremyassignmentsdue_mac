# Project requirements

- Preserve the deadline agenda layout and last-known-good cache unless the user explicitly requests a change.
- The user does not accept repeated Keychain approval dialogs. Never run interactive credential probes, repeatedly read the secret during tests, or use the app's changing ad-hoc identity to prompt during refresh. Share the cached credential read, keep Keychain interaction disabled, and retain saved content when silent access fails. Never print or commit a token.
- Keep real academic records, feedback PDFs, API evidence and application-support data outside this public repository. Tests use synthetic fixtures.
- Use native SwiftUI controls, semantic typography/colours and system accent. Document actual visual/accessibility verification rather than claiming blanket HIG certification.
- Treat important academic content as reusable: assignment instructions, rubrics (including every collapsed rating description), marks with their source, lecturer feedback and submission metadata must be selectable or have a clearly named complete-copy action. Preserve course/assignment context and distinguish criteria from assessed feedback. Copy/share is user initiated; never automatically send academic content to an AI service.
- Before adding a quality-of-life feature, check current official Apple documentation through Context7 for native text selection/copy commands, selection-aware context menus, Quick Look, Transferable/FileRepresentation, drag and drop, ShareLink and standard file actions. Prefer those APIs to custom gesture, clipboard, menu or preview infrastructure.
- Use the user's macOS accent and semantic system colours. Use semantic typography and verify larger text on macOS specifically; `.font(.body)` alone is not evidence that macOS responds to iOS Dynamic Type settings. Test wrapping, scrolling, keyboard and accessibility at supported reading sizes.
- Inspect Canvas UI or the user's own authenticated request flow when it resolves a concrete feature/accessibility/API question. Keep requests scoped to the user's data, retain read-only behaviour, and never commit captured session or network secrets. Reverse engineering is an optional research technique, not a prerequisite for features already covered by documented native APIs.

- Before changing interactions, research comparable apps/developer patterns and consult current official SwiftUI documentation through Context7 plus the Apple Human Interface Guidelines. Keep the approved layout and document the sources and what was actually tested.
- Ground substantial UX changes in NN/g interaction design, information design and information architecture, then correlate the findings with Apple HIG. Scope student tasks, hierarchy, discoverability and quick access before another visual pass. Include typography, semantic colour, interaction states, purposeful motion and Reduce Motion. Verify that labelled disclosure rows and visible toolbar bezels have comfortable real hit regions; native appearance or a successful centre click alone is insufficient.
- Builds, tests and reinstallations must never delete, reset or replace the saved Canvas API key. Keep using the existing shared cached Keychain reader; saving a replacement key requires the user's explicit request.

- Module materials: automatically discover Canvas module/week files; support dragging individual ready files and saving one module or all modules to Downloads, preserving Canvas names/order. Do not require uploads or include student submissions in teaching-material exports.
